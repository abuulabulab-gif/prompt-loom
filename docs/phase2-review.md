# フェーズ2 総合チェック指示書

フェーズ2で12機能＋インフラ改善が入った。本番化前に総合点検する。
Claude Code で下記を順に確認し、問題があれば修正、各項目の結果を報告すること。

---

## 1. ビルド・動作の健全性

- [ ] `npm run build` がエラー・警告ゼロで通るか
- [ ] `npm run dev` で起動し、コンソールにエラー/warningが出ていないか
- [ ] ダークモード・ライトモード両方で表示が崩れていないか
- [ ] スマホ幅（〜430px）・PC幅（900px+）でレイアウトが崩れないか
- [ ] リロード後もデータ（キャラ・ログ・サムネイル・LoRA・バージョン）が復元されるか

## 2. データ整合性（最重要）

フェーズ2で Character 型に多数のフィールドが増えたはず。確認：

- [ ] 新フィールド（サムネイル参照・LoRA・バージョン履歴等）が `saveState` に含まれ永続化されているか
- [ ] 古いデータ（フィールドが無い状態で保存されたキャラ）を読み込んでもクラッシュしないか（後方互換）
- [ ] サムネイルが `thumbs` テーブルに分離保存され、state row を肥大化させていないか
- [ ] 共有URL（#15）でインポートしたキャラが既存キャラと衝突（同一id）しないか

## 3. 機能の重複・競合チェック

似た役割の機能が増えた。UIの渋滞・操作の二重化がないか確認：

- [ ] 🎲ボタンが2種（#6ランダムインスピ＝ブロック単位 / #13バリエ＝全体）。アイコンやラベルで区別がつくか。紛らわしければ #13 を別アイコンに
- [ ] 「保存・復元」系が3つ（#9バージョン管理 / #15共有URL / 既存JSON書き出し）。それぞれ役割が明確か、ヘルプやラベルで違いが分かるか
- [ ] 表情プリセット(#3)・ネガ補完(#5) と既存タグボタンで、同じタグを二重に追加できてしまわないか（hasTag判定が効いているか）
- [ ] ショートカット（#1）が入力欄フォーカス中に誤発火しないか（textarea入力中に `[` `]` `P` `N` `1`〜`6` が押せるか）

## 4. アコーディオン化の状況

- [ ] ブロック内のタグカテゴリ（髪色・髪型・眉・メイク等）の折りたたみは実装されたか
- [ ] 未実装なら #17シンプル/詳細モードで代替できているか、それともカテゴリ単位の折りたたみが別途必要か判断する
- [ ] お気に入り（★）がブロック最上部に固定表示されているか

## 5. Tailwind移行の品質

- [ ] 残り55箇所のインラインは本当に動的値のみか（`block.color` `c.color` 等）
- [ ] 動的値でも「色だけインライン、レイアウトはクラス」に分離できているか
- [ ] ライトモードの固定濃色（`#2e1e0d` `#1e2860` 等）はトークン化されたか

## 6. 当初ロードマップとの整合（方針確認）

フェーズ2は便利機能中心だった。当初の核心だった以下が後回しになっている：

- [ ] キャラクターノート（`docs/character-note-spec.md`）= 設定シート・プロンプトログ・タグ対応表
- [ ] これはユーザー本人が「スプレッドシート置き換えで自分が使いたい」と最重視していた機能
- [ ] フェーズ3で実装予定だが、便利機能が揃った今、次の優先実装候補として認識しておく

## 7. プロンプトログの既存履歴との関係

- [ ] 既存の「プロンプト履歴20件」機能は今どうなっているか
- [ ] character-note-spec のプロンプトログに統合する前提だが、現状で二重に存在していないか確認

## 報告フォーマット

各セクションについて「✅問題なし / ⚠️要修正（内容）/ 🔧修正済み（内容）」で報告すること。
重大な問題（データ消失・クラッシュ・後方互換崩れ）があれば最優先で対応。
